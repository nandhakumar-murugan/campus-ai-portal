1. Architecture Overview

High-Performance Campus Intranet Mesh AI Supercomputer

The Campus AI Supercomputer aggregates idle RAM, VRAM, and CPU cores from student laptops across the campus Wi-Fi network to run 100% private, offline neural network models. Features a Node.js primary server handling telemetry and real-time P2P coordination, failing over across nodes to maintain uptime.

5. Data Structures & State

In-memory caching and JSON structures

  • registeredNodes: Array loaded from registered_contributors.json
  • liveUsageMap: Map storing heartbeats: Map<ip, {cpuPercent, usedRAMGB, totalRAMGB, ramUsagePercent, hostname, lastReportedAt}>
  • realDiscoveredNodes: Combined dynamic map of Host + Registered + ARP nodes
  • lastCpuMeasure: Retains CPU ticks for precise load calculations
  • realWifiDetails: { ssid, speedMbps, rxMbps, txMbps, signalPercent, radioType, band, channel }

6. Core Server Functions

Internal logic inside server.js

getRealSystemSpecs()Fetches host RAM, CPU load, uptime, and interfaces.
getRealCpuPercent()Computes instantaneous CPU utilization from differential OS tick counts.
getPrimaryHostIP()Selects best IP (prioritizes Wi-Fi > campus subnet > eth0).
scanRealArpDevices()Parses arp -a to build subnet map every 3s.
broadcastRealtimeState()Pushes metrics to clients over WebSocket.
processRealPrompt()Handles failover sequence: Primary Node → P2P Node → Fallback Rules.
generateIntelligentAnswer()Fires internal rule-engine if all LLMs are down.

7. Subnet & ARP Discovery

Dynamic peer identification

Node.js spawns a child process running arp -a every 3 seconds to parse the local routing table. Recognized IPs are validated against registeredNodes to update connectivity status dynamically.

8. Port Scanner Engine

Probing device capabilities

Security: The port scanner relies on internal intranet traffic. Be mindful of aggressive sweeping.

scanDevicePorts(ip) loops over predefined TCP ports using non-blocking sockets. Includes: 11434 (Ollama), 3000 (Node Server), 8888 (Jupyter), 7860 (Gradio), 8501 (Streamlit), 5000 (Flask), 8000 (FastAPI), 445 (SMB), 139 (NetBIOS), 3389 (RDP), 22 (SSH).

9. LLM Inference Pipeline

Fail-safe prompt handling

Inbound requests to /v1/chat/completions are routed through processRealPrompt(). It attempts inference on localhost (11434). If unavailable, it delegates to known peer nodes. Finally, it falls back to generateIntelligentAnswer().

10. Pooled Compute Math

Aggregate metric calculation

const onlineContributors = registeredNodes.filter(n => n.status === 'Online'); const pooledRAM = onlineContributors.reduce((sum, n) => sum + n.ramGB, 0); const pooledVRAM = onlineContributors.reduce((sum, n) => sum + n.vramGB, 0);

11. Live Usage Monitoring

Agent reporting mechanism

The contributor agent (via contributor-agent.html or headless script) routinely POSTs to /api/report-usage to populate liveUsageMap. Dead nodes (no report for >15s) are purged.

16. Student Benefits & Value Analysis

How this system empowers campus developers

Core Value: Provides 100% free, unlimited local AI compute without requiring credit cards, paid API keys, or external cloud subscriptions.
  • Zero Cost Barrier: Eliminates subscription fees like ₹800/month for GitHub Copilot or ₹1600/month for ChatGPT Plus.
  • Firewall Independence: Bypasses restrictive campus network rules by serving models over local intranet IPs (172.16.x.x).
  • Zero Network Latency Lag: Operates at gigabit Wi-Fi speeds (573+ Mbps) without external internet bottlenecks.
  • Resource Pooling: Aggregates idle student laptop RAM/VRAM into a unified campus supercomputing cluster.
